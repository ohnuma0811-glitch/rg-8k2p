# 対戦のレース（M4-C1。アイテムなし）の設計書

- 日付: 2026-10-23
- 全体の設計書: `docs/superpowers/specs/2026-10-13-race-game-design.md`（2章 VS RACE、11章 通信）
- M4-A: `docs/superpowers/specs/2026-10-22-gamecode-design.md`、M4-B: `docs/superpowers/specs/2026-10-22-lobby-design.md`
- M4-C は2つに分ける（2026-10-23 のユーザーの判断）。M4-C1（この設計書）: アイテムなしで対戦のレースを走る。M4-C2: アイテムをそろえる。
- 全体の設計書とちがう所は、この設計書を正とする（9章）。

## 1. 目的

- 待合室でコースが決まったら、走る人全員が同じコースで、同時にスタートして3周を競う。
- 日本とマレーシアで、通話しながら実際に走れること（GO! のずれ0.1秒以内が目標）。
- M4-C1 ではアイテムの箱を置かない。電波の遅れや車の動きのなめらかさを、アイテムなしで先に確かめる。

## 2. レースの流れ

1. コースが決まる
   - 待合室で全員が READY → 投票でコースが決まる →「〇〇が選ばれました！」を3秒（M4-B）。そのあと、走る人（`/room/racers`）全員がレースの画面へ。
   - 5台に足りない分を CPU で埋める（2人 → CPU 3台、3人 → 2台、4人 → 1台、5〜8人 → なし）。CPU のキャラは、走る人が選んでいないキャラから選ぶ（足りなければ重なってもよい）。名前はキャラの名前。
   - 投票の途中で待合室に来た人は、このレースには入らず、待合室で待つ。
   - 投票で同じ数のコースが並んだときは、まだ走っていないコースを優先する。その中から（全部走っていれば、並んだ中から）ランダム（2026-10-23 のユーザー依頼）。「走った」は、待合室が空になるまでの間に、このみんなで走ったコース（`/played`）。5コース全部を走ったら、`/played` を空にして、また最初から数える。
2. スタート
   - コースが決まった端末が、`/race` に「スタートの時刻＝今のサーバーの時刻＋8秒」を書く（早い者勝ちで1回だけ。transaction）。
   - 各端末は、サーバーの時計とのずれ（`.info/serverTimeOffset`）を直した時刻で、3・2・1・GO! を出す。8秒の間に、コースの準備とスタート前のカメラの動きをする。
   - スタートの位置（並び順）は、`/race` に書いた順。スタートダッシュは SOLO と同じ。
3. 走る
   - 自分の車は自分の端末で動かし、1秒に10回 `/race/karts/{車}` に書く。
   - ほかの人の車は、届いた位置のあいだをなめらかにつないで（補間）、少し遅らせて表示する。
   - CPU は、まかされた端末（4章）が動かして、同じように書く。
   - 車どうしは軽く押し合うだけ。押されて動くのは自分の車（と、自分が動かす CPU）だけ。
   - アイテムの箱は置かない（M4-C2 で入れる）。
4. ゴール
   - ゴールのタイムは、各自の端末が「スタートの時刻から何秒か」で決め、`/race/goals/{車}` に書く（電波の遅れは順位に入らない）。
   - ゴールした人の車は、SOLO と同じように走り抜けて画面がフェードアウトする。そのあと、カメラが「まだ走っている人の車（CPU は入れない）の中で、いちばん遅い車」の上空へ一瞬でワープし、画面が明るくなる。上空からゆっくり回りながら、その車を追う。いちばん遅い車が入れかわったら、カメラも移る（2026-10-23 のユーザー依頼）。
5. 終わり
   - 人の車が全員ゴールしたら、最後の人のゴールの映像が終わったところで終わる。CPU が残っていても、そのときの順位で決める。
   - 1位の人がゴールしてから3分で終わる。最後の10秒は、画面の真ん中に 10・9・…・1 と出し、0 で終わる（2026-10-23 のユーザー依頼）。
   - 結果の画面: 順位・顔・名前・タイム。ポイントは出さない（2026-10-23 のユーザー依頼）。ゴールしていない車のタイムは「—」。5秒たったら待合室に戻る（READY は外れた状態）。
6. 途中で抜ける・切れる
   - レース中の一時停止ボタンの中身は「QUIT」だけ（対戦ではレースは止まらない）。押すと待合室に戻る。その人の車は消えて、最下位あつかい。
   - 書いた時刻が3秒より古い車（電波が切れた）は消えて、最下位あつかい。
   - レース中に来た人は、待合室で待つ（今のレースのコースと、走っている人の名前を出す）。READY は、レースが終わってから。

## 3. データの置き場所（Firebase Realtime Database）

| 場所 | 中身 | 読む・書く |
|---|---|---|
| `/room/phase` | `lobby` / `voting` / `decided` / `racing` | M4-B の決まりに、`decided` → `racing` → `lobby` を足す |
| `/race` | `id`（投票の番号と同じ）、`course`、`startAt`（サーバーの時刻）、`racers/{uid}`（名前・キャラ・並び順）、`cpus/{c0..}`（キャラ・並び順）、`host`（CPU を動かす端末の uid）、`scores/{uid}`（決めたときの点数）、`firstGoalAt` | GAME CODE で入った人が読む。作るのは1回だけ（transaction）。`host` は引き継ぎのときだけ変えられる |
| `/race/karts/{車}` | `x` `y` `z`、向き、進む向き、速さ、ドリフト、周回、進んだ距離、書いた時刻 | 人の車は本人だけ、CPU の車は `host` だけが書く |
| `/race/goals/{車}` | ゴールのタイム（秒）か `quit` | 人の車は本人、CPU は `host`。一度書いたら書きかえられない |
| `/lobby/{uid}/score` | 性能の点数（4章） | 本人 |
| `/played/{course}` | 走ったコース（true） | 入れる人が読む・書く。レースが始まるときに足す。待合室が空になったら、チャットと一緒に消す。5コースそろったら空にする |

- 順位は、どの端末も同じ計算で決める: ゴールのタイムの速い順 → まだ走っている車は進んだ距離の順 → 最後に QUIT と切れた車。
- 通信の量: 1台あたり1秒に10回、1回約150バイト。5台で1レース（約2分）約1MB。無料の枠で足りる。

## 4. CPU を動かす端末（2026-10-23 のユーザーの判断「簡単にしたもの」）

- 待合室にいる間、各端末が点数を測って `/lobby/{uid}/score` に書く。点数のもとは、1秒に画面を描けている回数と、サーバーとの往復の時間（とそのばらつき）。電波の安定を重く見る。
- コースが決まったとき、走る人の中で点数がいちばん高い端末に CPU を全部まかせ、`/race/host` に書く。
- `host` の車のデータが3秒止まったら、残っている中で点数がいちばん高い端末が引き継ぐ（transaction で1台に決まる）。引き継いだ端末は、CPU の最後の位置から動かし続ける。
- 全体の設計書 11.2 の「CPU を分けて持たせる」「重くなったら移す」はしない。

## 5. 守り（ルール）

- `/race` を読み書きできるのは、GAME CODE で入った人（M4-A の「入れる人」）だけ。GM は読む・消す。
- `/race/karts/{uid}` と `/race/goals/{uid}` は本人だけ。`/race/karts/c*` と `/race/goals/c*` は `/race/host` の人だけ。
- `/race/goals/*` は一度書いたら書きかえられない。
- `/race` の作り直しは、`/room` が `decided` のときだけ。
- 自動のテスト（Emulator）で確かめてから、KENTA にルールを貼りかえてもらう。

## 6. ファイル構成（予定）

- `src/net/race.js`（新しく）: `/race` を作る・スタートの時刻・ゴール・順位・終わりの判定・CPU の host と引き継ぎ。サーバーは引数でもらう（テストではメモリの作り物）。
- `src/net/sync.js`（新しく）: 車の様子を1秒に10回送る、届いた様子をなめらかにつなぐ（補間）。
- `src/net/perf.js`（新しく）: 待合室で点数を測る。
- `src/main.js`（直す）: 対戦のレースの画面（スタート、ほかの車の表示、ゴールのあとの上空カメラ、最後の10秒、結果、QUIT）。
- `src/lobbyScreen.js`（直す）: `decided` のあとレースへ。レース中に来た人の表示。点数の測定。
- `src/net/room.js`（直す）: 票を数える `tally` に、走ったコースを渡す（同じ数ならまだ走っていないコースを優先）。
- `database.rules.json`（直す）: `/race`、`/room` の `racing`、`/lobby/{uid}/score`、`/played`。
- テスト: `tests/race.test.js`、`tests/sync.test.js`、`tests/perf.test.js`、`tests/rules/`。

## 7. 確かめ方

- `node --test`: スタートの時刻（ずれを直したカウント）、補間（あいだの位置、古いデータ、3秒で消える）、順位（ゴール・距離・QUIT・切れた）、終わり（人が全員ゴール・1位から3分・最後の10秒）、上空カメラが追う車（人の中でいちばん遅い車、入れかわり）、CPU の host の決め方と引き継ぎ、CPU のキャラの選び方、同じ数のときにまだ走っていないコースが選ばれる（全部走ったら空にする）。
- ルールのテスト（Emulator）: 5章のとおり。
- ブラウザ: 同じパソコンで2つのブラウザ（`localhost` と `127.0.0.1`、別の人として）で走る。
- 最後に KENTA に、日本とマレーシアで実際に走ってもらう。

## 8. M4-C1 に入れないもの

- アイテム（箱・使う・当たる・稲妻・ぺしゃんこ）の同期（M4-C2）。
- ポイントと合計の順位。
- BATTLE（M5）。

## 9. 全体の設計書から変わる所

- 2章: 結果の画面にポイントを出さない。終わり方（人が全員ゴール、1位から3分、最後の10秒）とゴールのあとの上空カメラを足す。
- 11.2: CPU は1台の端末にまとめ、引き継ぎは電波が切れたときだけ。
- 11.4: `/race` の中身を3章のとおりにする。
