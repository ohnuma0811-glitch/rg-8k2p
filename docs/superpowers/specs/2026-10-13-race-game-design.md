### 成功の基準

1. 日本とマレーシアの端末で同じレースを走り、相手の車がなめらかに動いて見える。
2. 6歳の Soki がボタン操作で3周を走りきれる。9歳の Kyugo が「がんばれば CPU に勝てる」と感じる。
3. GAME CODE を知らない人は、対戦（VERSUS）に入れず、家族の遊べる時間を減らせない。SOLO は URL を知っていればだれでも遊べる（2026-10-14 のユーザーの判断: 大事なのは、知らない人が対戦で遊んで家族の時間が減ったり費用がかかったりしないこと）。
4. 費用は0円のまま。Firebase は無料プラン（カードの登録なし）なので、使いすぎても止まるだけで請求は来ない。SOLO はサーバーをほとんど使わない（遊べる時間を書くだけ）。
5. 安い Android タブレットでも、レース中に30fps以上を保つ（新しいスマホは60fpsが目標）。
6. 外国の友達が、説明なしに GAME CODE の入力からレースの開始までできる。

## 2. 画面の流れ

```
タイトル: 4つの遊び方から選ぶ（2×2 に並べる。2026-10-14 のユーザー依頼）
  SOLO RACE（1人で CPU と競う） / TIME TRIAL（1人で練習） / VS RACE（対戦） / BATTLE（バトル）
  まだ作っていない遊び方を押すと「○○ is coming soon!」と出す
  （うしろでコースがゆっくり回り、その前、文字のうしろに Kyugo と Soki の絵を左右に大きく出す。
   Kyugo は赤い T シャツでツンツン頭、Soki は青い T シャツで坊ちゃん刈り、前歯が1本ない。2026-10-14 のユーザー依頼）
  │
  ├─ SOLO RACE（これまでの SOLO）
  │    名前入力 → キャラ選び → コースの紹介（3秒）→ レース（自分＋CPU 4台の5台、3周）→ 結果
  │    → もう一回 / タイトルへ
  │
  ├─ TIME TRIAL（追って作る）
  │    1人で走る練習。コースを1つ選んで、3周のタイムを計る（CPU なし）
  │
  ├─ BATTLE（追って作る）
  │    マリオカートのバトルのように、アイテムで攻撃し合い、3回攻撃されたら負け。
  │    人数・CPU・コース・GAME CODE が要るかなど、詳しくは作る前に決める
  │
  │  コースの紹介: レースが始まる前に毎回、タイトルと同じようにコース全体をゆっくり回って映し、
  │  「COURSE」とコースの名前を大きく3秒出す（暗くしない。2026-10-14 のユーザー依頼）。遊べる時間には数えない
  │  スタートの前のカメラ: コースの紹介のあと、カメラがスタートの列の前（自分の車の34m前）から、正面を向いた車たちを見て、
  │  横へふくらみながら車たちの上を通りすぎ、向きを変えて、走るときのカメラの位置（自分の車の後ろ）で止まる（4秒）。
  │  そのあと「3、2、1、GO!」が始まる。カメラが動いている間の DRIFT は、スタートダッシュに数えない（2026-10-14 のユーザー依頼）
  │
  └─ VS RACE（これまでの VERSUS）
       GAME CODE 入力（4けた、数字ボタン）※その端末で有効なコードが残っていれば飛ばす
         ▼
       名前入力 → キャラ選び
         ▼
       待合室（ロビー）：全員が同じ1つの部屋。入っている人の名前とキャラが並ぶ。性能を測る
         プレイヤーが2人以上いれば、だれかが START を押せる
         → 5秒の準備（その間に入った人も一緒に走る）→ 5台に足りない分を CPU で埋める
         ▼
       レース（3周）→ 結果（順位、タイム、ポイント）
         ▼
       待合室に戻る
```

- 結果の画面（2026-10-14 のユーザー依頼）: 「RESULTS」と表はタイトルのロゴと同じ文字（Racing Sans One）。1行ずつ、順位・キャラの顔のアイコン・名前・タイム・ポイント。自分の行は黄色。
- ポイント: 1位から 10・8・6・5・4・3・2・1。5台のレースなら5位は4ポイント。1位の行から順に、0 からカウンターのように数え上げ、数え終わるとぽんと大きくなる。いまはそのレースのポイントだけ（何レースかの合計はまだない）。
- 名前入力: A〜Zボタン、アルファベットだけ、最大12文字、最近の名前を表示。
- キャラ選び: 8人。同じキャラを選んでもよい。そのときは車の色だけ変わる。
- VERSUS の台数: プレイヤー2人 → CPU 3台、3人 → 2台、4人 → 1台、5〜8人 → CPU なし（合計5〜8台）。1人では START を押せない（SOLO で遊ぶ）。
- 部屋コードは使わない。GAME CODE で入った人は全員、同じ待合室に入る。
- レース中に来た人は、待合室でレースの順位を見ながら待ち、次のレースから参加する。
- 9人目からは待合室で待ち、次のレースで空きがあれば入る。入れる順番は、待合室に入った順。
- SOLO のレース中は、右上の一時停止ボタンで止められる（つづける / タイトルへ）。
- レース中は右上に一時停止ボタンがある。対戦中はレースが止まらないので、中身は「QUIT」（抜ける）だけ。抜けた車はその場で消え、順位は最下位扱い。
- 待合室に、音の ON/OFF、操作の切り替え、定型文の言語（歯車ボタン）と、キャラの選び直しがある。
- 待合室で文字のチャットができる（2.1）。

### 2.1 待合室のチャット

- 定型文のボタンと、自由に打つ文章の両方が使える。
- **定型文**は、読む人が選んだ言語（English / 日本語）で出る。送るのは定型文の番号だけで、受け取った端末がその人の言語に直して表示する。例: Kyugo が日本語の画面で「いいしょうぶだった！」を押すと、English を選んだ人には「Good game!」と出る。
- 言語は待合室の歯車ボタンで選び、その端末で覚えておく。最初は端末の言語の設定に合わせる（日本語なら日本語、それ以外は English）。言語で変わるのは定型文だけで、ほかの画面は英語のまま。
- 話すのは基本的に音声通話。チャットは、通話をつなぐ前の声かけや、ちょっとした合図に使う。
- 定型文（最初の案。あとから足せる。通話の2つは一番上に並べる）:

| English | 日本語 |
|---|---|
| Let's call on LINE! | LINEを つなごうよ！ |
| Let's call on WhatsApp! | WhatsAppを つなごうよ！ |
| Hello! | こんにちは！ |
| Ready? | じゅんび できた？ |
| Let's go! | いくよ！ |
| Wait a sec! | ちょっと まって！ |
| Don't press START yet! | まだ STARTは おさないで！ |
| One more! | もう いっかい！ |
| Good game! | いいしょうぶだった！ |
| Nice! | ナイス！ |
| So close! | おしい！ |
| I'll win next time! | つぎは まけないよ！ |
| Bye! | またね！ |

- **自由に打つ文章**は、スマホのキーボードで打つ（日本語も英語も打てる）。翻訳せず、打ったままの文字で出す。1回100文字まで。
- 送れるのは1秒に1回まで。
- 残すのは最新の50件。新しい GAME CODE を出すと、それまでのチャットは消える。
- メッセージの横に、送った人の名前とキャラの小さな顔。
- レース中はチャットを出さない（運転のじゃまになるので）。レースから戻ると、その間に来たメッセージが見られる。
- GM はメッセージを1件ずつ、または全部消せる。

## 3. GAME CODE（対戦に入れる人を限る）

### 3.1 遊ぶ人

- GAME CODE が要るのは VERSUS（対戦）だけ。タイトルで VERSUS を選ぶと、GAME CODE（4けたの数字）を入れる画面が出る。合っていれば先に進める。SOLO は GAME CODE なしで遊べる。
- 遊ぶ人はアカウントを作らない。Firebase の名前のない仮ログイン（匿名認証）を使う。
- コードが合っているかは Firebase のルールが確かめる。今日のコードはサーバーにだけあり、遊ぶ人の端末からは読めない。プログラムにも書かない。
- 一度入れた端末は、そのコードが切れるまで聞かれない。
- コードは、出した時から次の日本時間の深夜2時まで有効（マレーシアでは深夜1時）。0時〜2時のあいだに出したコードは、その夜の2時までになる。
- 1台の端末で5回まちがえると、そのコードの間はもう入力できない（「Too many tries. Ask the Game Master.」）。GM が解除するか、新しいコードが出れば、また5回入れられる。
- コードが切れたら、待合室から GAME CODE の画面に戻る。レースの途中で切れたときは、そのレースの最後まで走れる。
- ゲームのファイル（絵やプログラム）は、URL を知っている人なら見られる。SOLO も遊べる。コードがなければ、対戦の待合室には入れない。

### 3.2 ゲームマスター（KENTA）の画面

- URL の後ろに `#gm` を付けて開き、KENTA の Google アカウントでログインする。GM の操作ができるのは、あらかじめ登録した KENTA のアカウントだけ（Firebase のルールで決める）。
- スマホでも使えるよう、縦に並べた画面にする。iPhone ではホーム画面のアイコンからだと Google のログインがうまく出ないことがあるので、Safari のブックマークから開く。

| 操作 | 内容 |
|---|---|
| Set today's code | KENTA が数字ボタンで4けたを入れて、今日の GAME CODE にする。次の日本時間の深夜2時まで有効。コードが出ている間に新しく入れると、前のコードはすぐに使えなくなる |
| Stop | 今のコードをすぐに使えなくする。そのあと、また新しいコードを入れて出せる |
| Players | 今のコードで入った人の名前と、入った時刻の一覧 |
| Locked | 5回まちがえて入れなくなった端末の一覧（まだ名前を入れていないので、端末の種類〈iPhone / Android など〉と時刻で出す）。Unlock で解除すると、また5回入れられる |
| Play time | 時間の制限がある名前の、今日の使用時間。Reset で0に戻す |
| Daily limit | 1日の上限を名前ごとに変える（最初は20分） |
| Chat | 待合室のチャットを見る。1件ずつ、または全部消す |

### 3.3 守りの強さ

- 当てずっぽうは、1台につき5回まで。匿名ログインを作り直して試すことはできるが、Firebase が同じ回線からのアカウント作りを1時間あたりの回数で止める。家族と友達のゲームの守りとしては十分。
- Players の一覧で、知らない名前に気づいたら Stop して新しいコードを出す。

## 4. 遊べる時間の制限

- 名前が KYUGO か SOKI のときだけ、4つの遊び方（SOLO RACE・TIME TRIAL・VS RACE・BATTLE）を合わせて1日20分まで。ほかの名前は制限なし。
- 数えるのは「GO!」から、自分がゴールするまで、または QUIT / タイトルへ戻るまで。タイトル、待合室、結果の画面、ゴールしたあとほかの人を待つ時間、SOLO の一時停止中は数えない。
- 使った時間はサーバー（Firebase）に名前ごとに記録する。端末を変えても同じ20分の中で数える。SOLO も同じ所に記録する。ただし、サーバーに書けるのは、一度でも GAME CODE を正しく入れたことのある端末（家族と友達の端末）だけ。それ以外の端末の SOLO は、その端末の中だけで数える（知らない人が名前を KYUGO にして SOLO で遊んでも、家族の時間は減らない）。GM 以外は時間を増やすことしかできない。電波がないときは端末に記録しておき、つながったときに足す。残り時間は、端末の記録とサーバーの記録の多い方で決める。
- 1日の区切りは日本時間の深夜2時（深夜2時から次の深夜2時までの24時間。GAME CODE の期限とそろえる。2026-10-14 のユーザー依頼）。
- 20分を過ぎても、走っているレースは最後まで走れる。レースが終わったら「See you tomorrow!」を出し、待合室にもう一回にも進めない（タイトルへ）。
- タイトル・待合室と、名前を選んだあとに「Today: 12 min left」（1分を切ったら「Today: 45 sec left」）を出す。
- 時間が残っていないときは、名前を選んだところで「See you tomorrow!」。
- ゲームマスターは、使用時間のリセットと、名前ごとの1日の上限を変えられる（3.2）。
- 名前は自分で打つので、別の名前にすれば制限は逃れられる（今のゲームと同じ）。GM の Players 一覧で気づける。

## 5. キャラクター

### 5.1 一覧と能力

能力は3種類、1〜5の5段階。

- 加速: スタートやぶつかったあとに、どれだけ早くスピードに乗るか。スタートダッシュの伸びも決める
- 最高速: いちばん速いときのスピード
- ハンドル: 曲がりやすさと、ドリフトのしやすさ

| タイプ | キャラ | 加速 | 最高速 | ハンドル |
|---|---|---|---|---|
| 万能 | Kyugo / Soki / Penguin-man | 3 | 3 | 3 |
| スタートダッシュ | Rabbit Girl / Mouse Boy | 5 | 2 | 3 |
| 最高速度 | Big Tiger / Rampage Elephant | 2 | 5 | 2 |
| コントロール重視 | Lightning Cat | 3 | 2 | 5 |

- 数字は最初の値。実際に走らせて、強すぎるキャラが出ないように調整する。
- 1〜5の数字を実際の速さや曲がり方に直す表は、1つのファイル（`src/game/stats.js`）にまとめ、そこだけを直せば調整できるようにする。

### 5.2 見た目

- どのキャラも、丸い大きめの頭の「ちびキャラ」を、形の部品（球・円柱・円すい・箱）を組み合わせて 3D で作る。目と笑った口、髪型、腕でハンドルを握る（2026-10-14 のユーザー依頼）。小さなカートに乗る。確かめ用に、URL の後ろに `#front` を付けると車を前から見られる。見本: `docs/reference/kyugo-front.png`、`docs/reference/soki-front.png`。カートの色はキャラごとに決め、同じキャラが2人以上いるときは色を変える。
- Kyugo と Soki は、`09_子供たちのゲーム` のドット絵の特徴を 3D にする。
  - Kyugo: ツンツンの黒髪、赤いTシャツ（`#C11F0A`、胸に白いマーク）
  - Soki: おわん形の黒髪（前髪は横一直線）、青いTシャツ（`#1C3C88`、胸に白いマーク）
- Penguin-man は、KENTA からもらった絵（`docs/reference/penguin-man.webp`）の特徴を残す: 黒い体と白いおなか、頭のツンツンした毛、黒いサングラス（白い2本線の光）、黄色いくちばしと足、茶色のリュック。
- Rabbit Girl と Lightning Cat は女の子のキャラ。Mouse Boy は男の子のキャラ。
- 動物たちはオリジナル。Rabbit Girl はリボン、Mouse Boy は大きな丸い耳、Big Tiger はしま模様、Rampage Elephant は長い鼻と大きな体、Lightning Cat は稲妻もようのスカーフ、のように一目で分かる特徴を1つ付ける。

## 6. 操作

| 操作 | ボタン操作（スマホ・タブレット） | キーボード（パソコン） |
|---|---|---|
| ハンドル | 左下の ◀ ▶ | ← → |
| アクセル | 自動 | 自動 |
| ブレーキ／バック | 左下の ▼ | ↓ |
| ドリフト | 右下の大きいボタン（押している間） | 0 |
| アイテム | 右下の小さいボタン | Enter |

- アクセルは自動。曲がることだけに集中できる。
- 傾き操作はなし（M1 の実機確認のあと、ユーザーの判断で取りやめ。2026-10-14）。操作を選ぶ画面もない。
- タッチできる端末はボタン操作、パソコン（タッチできない）はキーボードで操作する。
- ボタンは指で押しやすい大きさ（画面の短い辺の11%、半径44〜72px。M1 の実機確認で大きくした）にし、ノッチやホームバーをよける。マルチタッチで同時に押せる。
- iPhone のダブルタップ拡大・文字の選択・長押しメニューは止める。

## 7. 走り

- 操作感はマリオカート64 にならう（2026-10-14 のユーザー依頼）。
- 曲がり方の目安（KENTA が Gemini に動画を見てもらった数字。2026-10-14）: ふつうに曲がると90度を0.5〜0.8秒、ドリフトでは0.3〜0.5秒。ドリフト中の車の向きのずれは30〜45度。ミニターボは1.0〜1.5秒。
- ふつうのハンドルは大回りで、きついカーブはドリフトで曲がる（マリオカート64 のように。2026-10-14 の実機確認で「ふつうのハンドルで小回りが利きすぎて、ドリフトを使う場面がない」ため）。最高速でいっぱいに切ると、ふつうは90度を約1.6秒（半径40m以上）、ドリフトで同じ向きにいっぱいに切ると約0.77秒（半径約20m）、ドリフトでハンドルを切らなければ半径約38m、反対に切るとほとんど曲がらず、ほぼまっすぐ進む（半径200m以上。2026-10-14 の実機確認）。遅いときのふつうのハンドルは、最高速のときの最大1.5倍まで（小回りしすぎない）。ドリフトが苦手でも、ブレーキで速さを落とせば、きついカーブを曲がれる。
- ドリフト: ボタンを押すと小さく跳ね、着地のときハンドルを切っていれば、その向きに滑り出す。ハンドルを切っていなければ跳ねるだけ（直線で何度も跳ねると少し遅くなる）。
- ドリフト中は、車の向きと進む向きがずれて、外側へ滑りながら曲がる。同じ向きに切るときつく、反対に切ると大回りになる。
- ミニターボ: ドリフトを続けると、タイヤの煙が0.7秒で黄、1.4秒で赤になる。反対に切って戻す（ボタンなら反対のボタンを押して離すだけでもよい）たびに、1段早く進む。赤のときにボタンを離すと約1.2秒加速する。白・黄で離しても加速しない。大きなカーブを1回ドリフトで回れば、赤まで届く（2026-10-14 の実機確認で、切り返しだけでは赤までためられなかったため。Gemini の答え「1.5〜2秒で赤」にも近い）。
- ジャンプ中にドリフトボタンを押してハンドルを切っていれば、着地してすぐドリフトになる。
- 逆走して柵に当たっても、逆向きのまま柵ぞいにそろうだけで、前向きには戻されない。
- マリオカート64 の「反対に切りっぱなしにするとスピンする」は入れない（子ども向け。必要なら後で足す）。
- **スタートダッシュ**: カウント「3、2、1、GO!」の「GO!」の0.2秒前〜0.05秒後に DRIFT ボタンを押すと、グンと加速する（2026-10-14 のユーザー依頼で ITEM から変更。M2 の実機確認で「判定が甘い」ため、0.3秒前〜0.1秒後から狭めた）。タイミングが合わなければ普通にスタート。キャラの「加速」が高いほど長く続く（0.5秒＋0.15秒×加速の数字）。止まっている間は DRIFT を押しても跳ねないので、ドリフトとは混ざらない。
- コースの外のダートでは遅くなり、車の後ろに砂ぼこりが上がる。その外側は柵。
- スピードは一定にならない（スピード計の数字が細かく動く。2026-10-14 の実機確認）: ハンドルをいっぱいに切ると最高速が約6%、ドリフト中は約4%落ちる。路面のでこぼこで、最高速が道では±1%、ダートでは±4%くらい上下する。最高速に近いほど加速がゆるくなり、ぴったり止まらない。
- 柵や壁にぶつかると、はね返ってスピードが落ちる。
- コースから落ちたときは、2秒後に、落ちた所のすぐ手前のコースに戻る。
- 描くときは、1秒に60回の計算のあいだをつないで車とカメラを置く（描く間隔がばらついても、キャラがぶれない。2026-10-14 の実機確認）。
- 車どうしは軽く押し合うだけ。強くはじき飛ばさない（通信の遅れによる位置のずれで、急に飛ばされないように）。

## 8. コース

### 8.1 最初のコース: Kenta Circuit

- 名前は Kenta Circuit（Kentaサーキット。2026-10-14 のユーザー依頼。はじめの仮の名前は Figure-8 Speedway）。

- 形は KENTA の手描きの絵（`docs/reference/course1-sketch.png`）のとおり。左下と右上のふくらみがあり、下の真ん中あたりで道が1回だけ交わる。真上から見た図: `docs/reference/course1-layout.svg`。
- 走る向き: 斜めの道を右上へ上る → 右上のふくらみ → 横の道を左へ → 左下のふくらみ → 斜めの道に戻る。
- きついカーブ（20mで52度以上曲がる所）は3か所だけにして、どれも大きく（80度以上）曲がる: ジャンプのあと、右下の角、左下から斜めの道への入り口。小さなくねくねは入れない（ほぼまっすぐ通れてしまうため。2026-10-14 のユーザー依頼）。
- 1周 1300m、30〜50秒（万能タイプで約40秒）。3周（2026-10-14 のユーザー依頼で2周から変更）。
- カーブの半径は、どこでも柵までの距離（16m）より大きくする。コースを作るとき、半径が足りない所だけを自動でならす（カーブの内側で、道・柵・土手が折れ返って、柵が道の上に立つのを防ぐ。2026-10-14 のレビュー）。そのため、いちばんきつい所でも20mで約57度（半径約20m）。
- 道幅 24m（カートの長さの約9倍。マリオカート64 くらい）。その外側のダートは片側 4m（細め）、さらに外側は柵。道のふちに赤白の縁石、道に白線。
- 斜めの道の、交わる所の手前に加速板とジャンプ台があり、横の道の上を飛び越える。ここがこのコースの見どころ。
- ジャンプ台は、赤い面に飛び出す方向を指す黄色い矢印をくり返し描き、側面は黄色と黒のしま（ひと目でジャンプ台と分かるように。2026-10-14 のユーザー依頼）。加速板はオレンジに黄色い矢印。
- ジャンプ台から飛び出す速さはいつも同じで、遅く走ってきても速く走ってきても、必ず向こう側の同じ所に着地する。
- 着地する側から逆向き（逆走やバック）に地面のない所へ入ろうとしても、飛ばずにふちで止まる（2026-10-14 の実機確認で、逆走して飛び越えてしまったため）。ふちで止まったまま逆向きに進もうとしていても、逆走の時間は数える（10秒でスピンして正しい向きに戻る）。
- 横の道は、交わる所を地面のまま走り抜ける。飛んでいる車と、下を走る車はぶつからない（高さで分ける）。
- 「?」の箱は、ジャンプの着地のあとと、横の道に、それぞれ横一列に並べる。取った箱は数秒後に元に戻る。
- スタートラインは横の道の、交わる所の手前。横（コースの外側）に満員の観客席。
- マリオカート64 のように、道の両側を高く囲む（2026-10-14 のユーザー依頼）: 柵は高さ2.5m、その外に高さ7mの緑の土手（しま模様）、土手の上に大きな木、柵と土手の間に大きな看板。観客席は10段。遠くの山は近く高く。土手は、ほかの道・交わる所・観客席の前には作らない。柵は、道の両側のどこにでも立てる。ただし、ジャンプ台の上と、ほかの道（交わる所・横の道）にかかる所だけは立てない。ジャンプの着地の近くにも柵を立てる（2026-10-14 のユーザー依頼「着地場付近の壁が消えている」）。土手は、柵があり、土手のふもと・中ほど・てっぺんのどこもほかの道にかからない所だけに作る。
- スタート地点の近くを通ると、観客席から歓声が聞こえる。近づくほど大きく、観客席のある側から聞こえる（13）。

### 8.2 スピード感（2026-10-13 のユーザー依頼）

- 最高速は万能タイプで時速約148km（41m/s。M1 の実機確認で、115km → 130km → 148km と上げた。「ゆっくりドライブしているよう」だったため）。
- 画角・車・キャラの大きさは、マリオカート64 くらいにする（2026-10-14 のユーザー依頼）。車は低くて細いゴーカートで、太いタイヤが目立つ。キャラは車に対して大きい（頭が車の幅くらい）。カメラは車の6.3m後ろ・高さ3.7m（キャラの頭のてっぺん約3mより上）から、車の14m先・高さ0.3mの所を見る。キャラは画面の下の方に大きく映り、まっすぐな道では頭も地平線より下に入る。車全体が画面に入る（2026-10-14 の実機確認）。カメラは車の進む向きに少し遅れて回り、カーブやドリフトでは車の横腹が見える。視野は58度で、速いほど広げ（最高速で+16度）、加速中はさらに+8度。
- 確かめ用の見方: URL の後ろに `#front` を付けると、レース中の自分の車を前から見られる（M2 から。キャラは名前とキャラ選びで決めるので、`#soki` `#jump` `#ramp` はなくした）。
- 加速中だけ、画面の端に流れる線を出す（まっすぐ走っているだけのときは出さない。2026-10-14 の実機確認）。
- 道の白線は4mごと、縁石のしまは2mごとにし、木と看板を道の近くに多く並べる（流れていく物を増やす）。
- 縁石・白線・木・看板で、流れていく物を増やす。

### 8.3 コースの作り方

- コースは、中心線が通る点を順に並べてなめらかな線でつなぎ、1周の長さに合わせて大きさを決める。道幅、加速板・ジャンプ台・「?」の箱の位置もデータで書く（`src/data/tracks.js`）。2つ目からのコースも同じ形で足せる。
- 順位は、周回数と、中心線のどこまで進んだかで決める。
- 逆走（コースと逆向き）を1秒以上続けると、キャラの頭の上に「↺ WRONG WAY!」を点滅させる。前向きに0.5秒走ると消える。逆走が10秒続いたら、1回スピン（約1秒。ハンドルは効かない）させて、正しい向きに戻す（2026-10-14 のユーザー依頼。はじめ30秒、M2 の実機確認で10秒に）。

## 9. アイテム

### 9.1 一覧

効果は基本的にマリオカートと同じ（Shell・Lightning・Star は、このゲームに合わせて変えている）。絵は任天堂のデザインを写さず、自分たちで描く。名前も任天堂の呼び名を使わず、普通の英語にする。

| アイテム | 効果 | 見た目 |
|---|---|---|
| Mushroom | 約1.5秒加速する。ダートでも遅くならない | 赤に白い水玉のキノコ。目は描かない |
| Shell | 使った時点で自分のひとつ前の順位の車を追いかけて当たる（9.3）。当たった車はスピンする | 赤いカメの甲羅（模様はオリジナル） |
| Banana | 後ろに置く。踏んだ車は、5秒間ハンドルの左と右が入れ替わる（スピンはしない。9.2）。踏まれるまで残る（コース全体で最大10個。超えたら古い物から消える） | 普通のバナナの皮 |
| Star | 約6秒、無敵。加速・最高速・ハンドルの全部が上がる（上がり方は M3 で決める）。ぶつかった車はスピンする。Shell・Banana・Lightning が効かない | 黄色い星 |
| Lightning | 自分以外の全員（CPU も）に稲妻が落ち、10秒間、ハンドルの左と右が入れ替わる | 稲妻 |
| Feather | その場で高くジャンプする（9.4） | 白い羽 |

### 9.2 左右の入れ替え（Lightning と Banana）

- Lightning は自分以外の全員に10秒間、Banana は踏んだ車だけに5秒間効く。
- ボタン操作・キーボードのどちらでも、左右が入れ替わる。
- 入れ替わっている間は、画面の端が黄色く光り、真ん中に「⇄」と残り秒数を出す。Banana を踏んだときは、黄色いバナナの皮が画面の前を横切る。
- Star で無敵の人には効かない。
- 入れ替わっている最中にもう一度 Lightning が落ちたり Banana を踏んだりしたら、残り時間は「今の残り」と「新しく効いた時間（10秒か5秒）」の長い方になる（2回で元に戻る、ということはない）。
- CPU は、10秒間ふらふらと走る。

### 9.3 Shell のくわしい動き

- 狙う相手は、使った時点で自分のひとつ前の順位の車（人でも CPU でも）。飛んでいる間に順位が変わっても、相手は変わらない。
- 速さは、使ったキャラの最高速の2倍。使った時のスピードではなく最高速で決めるので、止まりかけで使っても必ず追いつく。
- コースに沿って相手を追いかけるので、カーブや8の字の交わる所でも壁に当たらない。
- 甲羅は飛べないので、ジャンプ台は越えられない。甲羅の通り道にジャンプ台があると、そこで壁にぶつかって消える。つまり、ジャンプ台の先にいる相手には届かない。
- 間に障害物があると、そこで当たって消える。
  - 間にいる別の車: その車に当たる（その車がスピンする）
  - コースに置かれた Banana: 両方とも消える
  - 相手が Star で無敵のとき: 甲羅だけが消える
  - 相手が Feather で跳んでいるとき: 甲羅は下を通りぬけ、そのまま消える（よけられる）
- 1位で使ったとき（前に車がいない）は、前にまっすぐ飛び、5秒で消える。
- 相手がゴールしたり、通信が切れて消えたりしたら、甲羅も消える。
- 対戦では、使った人が「だれを狙って、いつ出したか」を1回だけ送る。各端末が同じように甲羅を動かし、当たったかどうかは当てられた人の端末が決める（11.1）。

### 9.4 Feather のくわしい動き

- 使うと、その場で高くジャンプする（ジャンプ台より少し低いくらい）。跳んでいる間も、少し左右に曲がれる。
- 跳んでいる間は、Shell と Banana に当たらない。
- 最初のコースでは、甲羅やバナナをよけるのに使う。
- 2つ目からのコースには、Feather で跳ばないと行けない近道を作る（今回は作らない）。

### 9.5 スピン

- Shell に当たったとき、Star の車にぶつかったときにスピンする（Banana ではスピンしない）。
- 見た目: 小さな爆発が起きて、キャラがカートごと上に吹き飛び、くるくる回りながら落ちてきて、着地してから走り出す。
- 細かい所（吹き飛ぶ高さ、回る回数、止まる時間）は、M3 で実際に動かしながら決める。

### 9.6 出やすさ

- アイテムは「?」の箱を取ると出る。上の真ん中でルーレットが回って決まる。持てるのは1つ。
- 後ろの順位ほど、Star・Mushroom が出やすく、上位は Banana・Shell・Feather が出やすい。
- Lightning は、下から3番目までの順位のとき（5台なら3〜5位、8台なら6〜8位）だけ、低い確率で出る。
- 順位ごとの確率の表は `src/game/itemOdds.js` にまとめ、走らせて調整する。

## 10. CPU

- 台数: SOLO は4台。VERSUS は、プレイヤーと合わせて5台になる分（プレイヤー5人以上なら0台）。
- 強さは1段階。中心線から少しずれたコース取りで走り、カーブではドリフトもする。アイテムも使う。
- CPU の最高速は、キャラの数字の98%。プレイヤーより後ろの CPU は最大12%速く、前の CPU は最大12%遅くする（離れすぎないように）。
- CPU 4台のうち2台は、スタートダッシュをする。
- Kyugo が「がんばれば勝てる」くらいに調整する。M2 の実機確認で、93%・8%では「スタートダッシュのあと全然追いついてこない」と弱すぎたため、上のように強くした（2026-10-14）。CPU と同じ運転のプレイヤーなら、1位でいられるのはレースの7割より短い。

## 11. 通信

### 11.1 同期のしかた

各端末が自分の車を動かし、位置を1秒に10回サーバーに送る。ほかの車は、届いた位置のあいだをなめらかにつないで（補間して）表示する。自分の操作が遅れなく反応するので、操作感がいちばん良い。

| 物 | だれが決めるか |
|---|---|
| 自分の車の位置・向き・ドリフト | 自分の端末 |
| CPU の車 | CPU を割り振られた端末（11.2）が動かして送る |
| アイテムに当たったか | 当てられた人の端末（自分の画面で当たったら当たり）。CPU は動かしている端末が決める |
| 「?」の箱から出るアイテム | 取った人の端末（順位で出やすさを変える） |
| 置いたバナナ・飛んでいる甲羅 | 出した人が「出た」こと（甲羅は狙う相手も）を1回だけ送り、あとは各端末が同じように動かす |
| Lightning | 使った人が「落とした」ことを1回だけ送り、受け取った各端末が自分の車（と、動かしている CPU）に効かせる |
| 順位とゴール | 各自のゴールした時刻で決める（遅れの影響なし） |
| スタートの合図 | START を押した人の端末が、スタートの時刻を送る（11.3） |

- 途中で電波が切れた人の車は、3秒止まったら消える。

### 11.2 CPU の割り振り

- 待合室にいるあいだ、各端末が次の2つを測ってサーバーに送る。
  - 描画の余裕: 1秒に何回、画面を描けているか
  - 通信: サーバーとの往復にかかる時間と、そのばらつき
- この2つを点数にして、点数の高い端末に CPU を分けて持たせる（CPU は多くても3台なので、1台の端末に2台まで。例: CPU 3台なら、上位2台が2台と1台）。SOLO では、CPU は自分の端末が動かす。
- CPU の計算そのものは軽く、重いのは全員が行う 3D の描画。そのため点数では、電波の安定を重く見る。
- レースの途中で、CPU を持っている端末が重くなったり電波が切れたりしたら、その CPU を次に点数の高い端末へ自動で移す。
- 割り振りは START を押した人の端末が決める。その端末が切れたら、残っている中で点数がいちばん高い端末が引き継ぐ。

### 11.3 スタートの合図と時刻のそろえ方

- スタートの時刻は、世界共通の時刻（UTC のミリ秒）で送る。日本とマレーシアの時差の影響は受けない。
- スマホの時計のずれを直すため、各端末は Firebase から「サーバーの時計とのずれ」（`.info/serverTimeOffset`）を受け取り、そのずれを直した時刻でカウントを出す。日本とマレーシアでも、GO! はほぼ同時（ずれ0.1秒以内が目標）。

### 11.4 データの置き場所（Firebase Realtime Database）

| 場所 | 中身 | 読める人 / 書ける人 |
|---|---|---|
| `/secret` | 今日のコード（GM が入れた4けた）、コードの番号、切れる時刻（日本時間の深夜2時） | GM だけ（遊ぶ人は読めない。ルールの中では使う） |
| `/attempts/{uid}` | コードの番号、入れた数字、回数、端末の種類、時刻 | 本人。回数は1ずつしか増やせず、5回まで。GM が読み、解除（消す）できる |
| `/access/{uid}` | 名前、入ったコードの番号、入った時刻 | 本人が書く（入れた数字が今日のコードと同じときだけ）。GM が読む |
| `/lobby/{uid}` | 名前、キャラ、性能の点数、つながっているか | コードが有効な人 |
| `/race` | 今のレースの状態、スタートの時刻、参加者、CPU の割り振り | コードが有効な人 |
| `/race/karts/{id}` | 位置、向き、速さ、ドリフト、周回、進んだ距離 | 書けるのはその車を動かす端末 |
| `/race/events` | アイテムを出した・当たった・Lightning など | コードが有効な人 |
| `/chat/{id}` | 送った人、名前、キャラ、定型文の番号か自由な文章、時刻 | コードが有効な人が読む・書く（自分の分だけ、100文字まで）。GM が消す |
| `/playtime/{名前}/{日本の日付}` | 使った時間 | 本人が足す。GM がリセット |
| `/limits/{名前}` | 1日の上限（分） | GM が書く。だれでも読める |

- 「コードが有効な人」とは、`/access/{uid}` のコードの番号が今のコードの番号と同じで、切れる時刻の前の人。
- 通信量の目安: 8人で1レース（3周、約2分）全員分約14MB。Firebase の無料枠（月10GB）で月700レースくらい。
- Firestore は1日の読み書きの回数に無料の上限があるので使わない。

## 13. 音

- 音のファイルは使わず、Web Audio でプログラムから作る。
- **BGM**: スーパーファミコンくらいの音を目指す。
  - 少しずつ高さをずらした音を重ねて厚みを出し、フィルターで音色を変える。
  - ドラム（バスドラム、スネア、ハイハット）もプログラムで作り、ベース・メロディ・ハモリ・ドラムのバンド編成。
  - 残響を付けて広い場所で鳴っているように聞かせる。
  - 曲はゲームを開いたときに一度だけ作っておき（OfflineAudioContext）、レース中は流すだけにする。
  - 曲はオリジナル。マリオカートの曲のメロディはまねない。
  - 曲: 待合室、コース（Kenta Circuit）、最後の周（同じ曲を少し速く）、結果。
- **効果音**: マリオカートを意識して、聞いた感じが似るように作る（音は一から作るので任天堂の音そのものではない）。
  - スピードに合わせて高くなるエンジン音、ドリフトのキュルキュル、火花の色が変わる音、ミニターボの「シュバッ」、スタートダッシュ、アイテムのルーレットのカラカラ、各アイテムを使う音、スピン、甲羅が当たった音、バナナを踏んだ音、稲妻、カウントの「ポーン、ポーン、ポーン、プォーン！」、周回の音（最後の周は特別な音）、ゴールのファンファーレ、観客席の歓声（スタート地点の近く）。
- **観客席の歓声**: 雑音を何層も重ねて、大勢の「ワーッ」というどよめきと、ときどき上がる「ウォー！」を作る。人の声の録音ではないので、言葉は聞き取れない。観客席に近づくほど大きくなり、観客席のある側から聞こえる（左右の聞こえ方を変える）。最後の周とゴールのときは、ひときわ大きくなる。
- 最初のタップで音を有効にする（iPhone・Android の制約）。
- 通話中の iPhone では、ゲームの音が小さくなったり鳴らなかったりすることがある。待合室の音の ON/OFF で消せる。
